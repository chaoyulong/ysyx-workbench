# 性能记录表（Performance Records）

每次性能优化后执行 `make perf` 记录结果，配合 `git checkout <commit>` 可复现当时代码的性能数据。

## 使用方法

```bash
make perf                    # 运行 microbench(test 规模), 输出: 仿真周期数/指令数/IPC + PERF 计数器
make sta                     # 综合(nangate45), 频率/面积见 build/sta/ysyx_23060082-500MHz/
make sta STA_PDK=icsprout55  # 换流片工艺综合
```

- **仿真周期数 / 指令数 / IPC**：`make perf` 输出中的 `total execution cycle / inst / instructions per cycle`
- **综合频率 / 面积**：`make sta` 后查看 `build/sta/ysyx_23060082-500MHz/`（时序报告给出可达频率，`synth_stat.txt` 给出 `Chip area`）
- **PERF 计数器**：`make perf` 输出的 `============ PERF ============` 表格（IFU/LSU 延迟、EXU 计算周期、指令类别占比）

## 记录步骤

1. `git log --oneline` 确认当前 commit
2. 执行 `make perf`，从输出抄录周期数/指令数/IPC 和 PERF 表格
3. 执行 `make sta`，从报告抄录综合频率/面积
4. 将数据填入上表（commit + 说明 + 数据），提交 `PERF.md`

## 说明

- **工艺**：`综合面积` **只在同一工艺内可比**（各行在"说明"列注明工艺）。教程的面积限制按 **nangate45** 判定；`make sta STA_PDK=icsprout55` 可切回 icsprout55 流片工艺，同一份 RTL 两者相差约 30%
- **取指总周期**：所有取指请求累计周期数（= 取指avg × 取指次数）
- **取指avg**：PerfReg 延迟组 0 的平均值。**注意**：命中是"请求即响应"(同拍)，而 PerfReg 在同拍 req+rsp 时读到的是**上一次**请求的时间戳，故该值实际接近"两次取指的平均间隔"，不是纯取指延迟
- **取指命中率 / 缺失avg**：icache 的 `io.miss`、`io.missDone` 两个脉冲统计而来；`缺失avg` 即**平均缺失代价**，也就是文档 TMT（总缺失时间 = 缺失次数 × 缺失代价）里的那一项
- **LSU访存总周期**：内存读+写累计周期数（= rd total + wr total）
- **LSU mem rd/wr avg**：内存读/写平均延迟（cyc/access）
- **LSU dev avg**：外设访问平均延迟（串口/键盘/CLINT/VGA 等）
- **EXU calc**：计算类指令总执行周期（当前单周期，= 计算类指令数）
- **calc/mem/branch/jump/csr/sys%**：指令类别占比（decoder 统计）
- 不同 commit 的计数器含义可能不同（如早期无 PerfReg、604d59c 起才有命中率），以当时代码输出为准
